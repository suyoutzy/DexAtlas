# 工程导航的论文依据与边界

核查日期：2026-10-18。

当前首页的六阶段是编辑性导航：目标 → 系统 → 方法 → 运行 → 评估 → 达成。阶段编号方便阅读，不表示全部工作严格串行，也不是成熟度等级。此次核实的文献没有把这六个名称、三个方法入口和全部箭头规定为统一标准流程。

上述文献的作用不同：综述提供跨研究的问题与方法组织，原始论文提供具体系统的数据流和实验。正式期刊或会议记录、明确的原始章节、可检查的实机验证，比仅凭项目名称或作者机构判断依据更稳妥；发表场所也不意味着论文给出的流程适用于全部项目。

原有 [MIT Robotic Manipulation](https://manipulation.mit.edu/)、[LeRobot](https://huggingface.co/docs/lerobot/il_robots)、[Isaac Lab](https://isaac-sim.github.io/IsaacLab/main/source/overview/core-concepts/task_workflows.html) 继续作为教材和实现参考。它们与论文共同支撑导航的合理性，不能合并宣称为统一学术标准。

## 哪些连接有直接依据

- **目标、系统、交互学习、实机运行、评估**：Shadow Hand 论文的任务说明、Figure 2 和结果部分可逐项对应。阶段之间的概括性连接仍是本项目的表达。
- **示范学习分支**：ALOHA 论文提供实际示范—策略—实机实验的案例；LeRobot 提供记录、训练、评估的实现流程。
- **设计与优化分支**：保留 MIT 教材对规划与控制的依据，不强行把上面的学习论文用于证明所有解析或优化方法。
- **评估 → 达成**：是本项目将测试结果与验收条件相比较的导航表达，并非上述论文独立命名的标准算法阶段。
- **评估 → 方法的反馈线、三个入口可组合**：表示工程迭代与组合的可能性，不能理解为每个组合都已在某项研究中验证。

本轮保留 9 个工程节点、13 条流程线、29 条用途线；只补充可定位的依据和解释，不新增推断出来的连接，也不改动 22 个词条与 32 条概念关系。

## 手内操作为什么连接目标与评估

“手内操作”属于任务或研究问题，同一任务贯穿设计、执行和评估。两条 `usage` 线说明在两个环节如何引用这个术语，并非包含关系或训练步骤，也不是完整列举它出现的所有环节。

| 用途线 | 在该环节的含义 | 原论文定位 |
| --- | --- | --- |
| 目标 → 手内操作：定义手内操作任务 | 确定让手中的物体达到指定姿态等任务要求；未指定必须采用某种算法。 | arXiv v5，第 2 节 Task and System Overview。 |
| 评估 → 手内操作：评估手内操作表现 | 检查同一任务的执行表现。论文统计连续重定向目标完成数，并明确掉落、目标超时与试验上限等终止条件。 | arXiv v5，第 6.2 节 Quantitative Results。 |

全图只有一个 `in_hand_manipulation` 节点。其位于空间中的位置不表示只属于某一阶段；这些用途也不表示手内操作仅发生在起点和终点。
